# 别吃灰视觉设计规范

日期：2026-06-10

## 参考来源

本设计规范基于用户提供的笔记应用截图提炼，用于指导“别吃灰”本地个人知识库管理应用的界面重构。截图呈现的是一个三栏笔记管理器：左侧导航、中间笔记列表、右侧详情编辑区。整体风格克制、干净、留白充足，适合知识整理、资料管理和长期阅读。

`design.md` 只描述视觉、布局、组件和交互气质。技术栈和工程架构另见 `technical-architecture.md`。

## 设计关键词

- 干净
- 安静
- 轻量
- 笔记感
- 收藏夹
- 本地资料库
- 低干扰
- 高留白
- 中性灰
- 信息分层
- 左侧导航
- 渐进式详情
- 卡片列表
- 轻编辑
- 可回看

## 整体气质

界面要像一个可信赖的个人资料管理器，而不是 AI 聊天产品、运营后台或营销型网页。

核心气质：

- 像笔记应用：适合长时间停留、阅读、整理。
- 像收藏管理器：信息密度适中，方便快速扫视。
- 像本地工具：稳定、直接、少装饰，不制造云产品的营销感。
- 像知识工作台：导入、查看、筛选、编辑、回顾都在同一套空间里完成。

用户打开应用后应该感觉：这里是自己的知识库，安静、清楚、可控。

## 色彩规范

### 主色调

以白色、浅灰和近黑为主。

建议色彩范围：

- 页面背景：`#FFFFFF`、`#FAFAFA`、`#F7F7F7`
- 左侧导航背景：`#FAFAFA` 或 `#F8F8F8`
- 卡片背景：`#FFFFFF`、选中态可用 `#F5F5F5`
- 边框线：`#ECECEC`、`#E5E5E5`
- 主文字：`#1F1F1F`、`#222222`
- 次级文字：`#777777`、`#8A8A8A`
- 弱提示文字：`#A0A0A0`

### 状态色

状态色只能作为小面积提示使用，不要大面积铺色。

- 导入中：克制蓝色，例如 `#2F72DF`
- 导入成功：克制绿色，例如 `#2F8F46`
- 导入失败：克制红色，例如 `#B64B3C`
- 热力图活跃度：使用单一蓝色阶梯，不混用多种色相

### 禁止倾向

- 不使用大面积渐变背景。
- 不使用紫蓝渐变作为主视觉。
- 不使用营销页常见的彩色光晕、玻璃拟态、装饰球。
- 不让界面被某一种强色统治。
- 不用高饱和色做大面积面板。

## 布局规范

### 桌面端主布局

参考截图采用三栏结构：

```text
左侧导航 / 中间列表 / 右侧详情
```

别吃灰采用渐进式三栏：

- 默认双栏：左侧导航 + 内容区。
- 在知识库中点击卡片后变成三栏：左侧导航 + 中间卡片列表 + 右侧卡片详情。
- 关闭详情后回到双栏。

### 左侧导航

左侧导航固定，宽度建议 `220px - 240px`。

结构：

- 顶部品牌区：应用名和本地知识库身份感。
- 醒目的 `+ 导入` 按钮。
- 主导航：Home、知识库、日历、搜索、AI 热点推荐。
- 底部辅助入口：设置、备份、导出。

视觉要求：

- 背景比主内容区略灰。
- 导航项高度稳定，行距舒展。
- 当前选中项使用浅灰底或深色底，但不要花哨。
- 图标可以使用线性图标，大小统一。
- 知识库文件夹放在“知识库”的下拉中，不把文件夹散落成主导航。

### 中间列表区

中间列表区承载“最近导入”“知识卡片”“热点文章”等列表。

视觉要求：

- 宽度适中，不要压缩到难以阅读。
- 列表项之间留出明确间距。
- 卡片内容最多展示标题、日期、摘要、标签、状态。
- 内容过长时截断，不撑开布局。
- 选中卡片使用明确但克制的背景变化。

### 右侧详情区

右侧详情区是阅读和轻编辑区域。

视觉要求：

- 宽度需要保证正文舒适阅读。
- 顶部使用面包屑或路径，例如“知识库 > AI 产品 > 某篇文章”。
- 标题字号明显大于正文。
- 元信息区域用两列标签式排布，例如来源、文件夹、更新时间、标签。
- 内容区以摘要、备注、原文预览分段展示。
- 编辑按钮和更多操作放在右上角或底部操作区，不干扰阅读。

## 卡片风格

卡片要像截图里的笔记列表项：轻、浅、低边界感。

规范：

- 圆角：`8px - 12px`
- 边框：使用极浅边框，或只用浅灰背景区分。
- 阴影：默认不使用明显阴影；必要时只用极轻阴影。
- 背景：白色或浅灰。
- 标题：中等粗细，清晰但不过度强调。
- 摘要：最多 2 到 3 行。
- 标签：小胶囊，浅灰底，文字中性灰。
- 日期：小号、浅灰，放在标题上方或卡片角落。
- 状态：导入中/成功/失败用小文字或小徽标，不做大色块。

卡片选中态：

- 可以使用深色背景配白字，或浅灰背景加边框。
- 不使用强烈发光、彩色描边或动效。

## 按钮规范

### 主按钮

`+ 导入` 是最重要的行动按钮。

规范：

- 放在左侧导航顶部区域。
- 高度略高于普通导航项。
- 可使用深色背景和白字。
- 文案保持短：`+ 导入`。

### 次级按钮

用于保存、取消、重试、打开原链接、移动文件夹。

规范：

- 使用浅灰背景或文字按钮。
- 不抢主按钮视觉权重。
- 保持稳定尺寸，避免文案导致按钮跳动。

### 危险按钮

用于永久删除等不可逆操作。

规范：

- 不在默认状态下突出显示。
- 需要二次确认。
- 使用克制红色，不使用大面积红色面板。

## 标签规范

标签参考截图中的浅灰胶囊。

规范：

- 小尺寸。
- 浅灰背景。
- 中性灰文字。
- 圆角 `6px - 8px`。
- 标签之间间距紧凑。
- `+ 添加标签` 使用同样样式，不做强按钮。

标签用于识别和筛选，不应该成为界面的主视觉。

## 热力图规范

Home 的知识活动热力图参考用户提供的 Token 活动图。

规范：

- 小方块网格。
- 方块圆角轻微，建议 `3px - 4px`。
- 默认无活动为浅灰。
- 活动强度使用蓝色阶梯。
- 月份标记放在底部。
- 右上角可以提供每日、每周、累计切换。
- 悬停显示当天导入文章数和文字数。
- 点击方块进入日历对应日期。

避免：

- 不做复杂图表框架。
- 不使用多色热力图。
- 不让热力图占满首屏。

## 弹窗规范

导入使用弹窗，不跳转独立页面。

规范：

- 居中弹窗或轻量抽屉均可，但第一版优先居中弹窗。
- 背景遮罩轻，不要过暗。
- 表单只保留必要字段：链接、文件夹。
- 新建文件夹入口在文件夹选择附近。
- 提交后允许关闭弹窗。
- 任务状态回到 Home 最近导入查看。

弹窗不要承载复杂多步流程。

## 文字和字号

参考截图使用清晰的现代无衬线字体。

建议：

- 中文字体优先系统字体：`Microsoft YaHei`、`Segoe UI`、`Arial`、系统 sans-serif。
- 页面标题：`28px - 34px`
- 区块标题：`18px - 22px`
- 正文：`14px - 16px`
- 次级信息：`12px - 13px`
- 行高：正文建议 `1.6 - 1.8`

文字风格：

- 文案短。
- 操作词直接。
- 少解释，多状态。
- 错误提示要告诉用户下一步可以做什么。

## 图标规范

图标应为线性、轻量、统一尺寸。

建议：

- 导航图标使用 `18px - 20px`。
- 操作图标使用 `16px - 18px`。
- 图标颜色跟随文字灰度。
- 不使用填充感很强的彩色图标。
- 不用自制复杂 SVG 插画作为界面装饰。

## 交互气质

交互要直接、稳定、可预期。

原则：

- 默认展示阅读态。
- 编辑操作按需进入。
- 用户操作后要有明确状态反馈。
- 导入任务不能静默运行，必须可见。
- 删除先进入回收站，永久删除再确认。
- 点击卡片展开详情，不打断当前列表上下文。

动效：

- 可以使用非常轻微的 hover 背景变化。
- 可以使用轻微过渡，例如 `120ms - 180ms`。
- 不使用夸张弹跳、缩放、拖尾或复杂转场。

## 空状态和错误状态

空状态要轻，不要营销化。

示例：

- 暂无收藏：显示“还没有收藏，点击导入添加第一篇文章。”
- 文件夹为空：显示“这个文件夹还没有卡片。”
- 搜索无结果：显示“没有找到匹配卡片，试试换一种描述。”
- 导入失败：显示失败阶段、失败原因、重试按钮。

错误状态需要保留用户已经输入的信息，例如 URL 和目标文件夹。

## 响应式规范

第一版桌面端优先。

窄屏规则：

- 左侧导航可折叠。
- 知识库从三栏降级为逐级进入：导航 -> 列表 -> 详情。
- 卡片网格降级为单列列表。
- 弹窗宽度使用屏幕安全边距。
- 文字不能溢出按钮或卡片。

## 避免事项

必须避免：

- 做成营销落地页。
- 做大 hero 区或宣传式首页。
- 使用大面积渐变、光晕、装饰球。
- 把 AI 问答做成唯一主舞台。
- 把评测工作台放进主应用导航。
- 把文件夹做成复杂无限层级。
- 在第一版引入过度复杂的编辑器视觉。
- 卡片阴影过重。
- 页面边框过多。
- 字号层级混乱。
- 按钮和标签颜色过多。
- 详情页信息挤在一起。
- 长文本撑破卡片。
- 弹窗里塞入多步复杂流程。

## 设计验收清单

实现界面时逐项检查：

- 是否一眼能看出这是个人知识库，而不是后台系统？
- 左侧导航是否安静、稳定、层级清楚？
- `+ 导入` 是否醒目但不过度花哨？
- 知识库默认双栏、选中卡片后三栏是否自然？
- 卡片是否轻、浅、容易扫读？
- 标签是否只是辅助信息，而不是主视觉？
- Home 热力图是否接近参考图的克制感？
- 最近导入状态是否清楚？
- 详情页是否适合阅读？
- 删除、失败、重试是否有明确反馈？
- 是否避免了大渐变、强装饰和营销式表达？
